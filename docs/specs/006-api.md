# SPEC-006 — REST API

- Status: Approved
- Sprint: 2
- Related: [004](./004-digital-diagnosis.md), [005](./005-leads.md)

## Principles

- Next.js Route Handlers under `src/app/api`.
- Handlers are thin: parse → validate (Zod) → call a service/repository → map to HTTP. No business
  rules in handlers.
- JSON only. Successful responses wrap the payload in `data`; errors in `error`.
- Messages are in Spanish because they can surface in the UI.

## Error format

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Revisa los campos marcados.",
    "issues": [{ "path": "email", "message": "Introduce un email válido, por ejemplo nombre@empresa.com." }]
  }
}
```

| Code               | HTTP | When |
| ------------------ | ---- | ---- |
| `INVALID_JSON`     | 400  | Body is not valid JSON |
| `VALIDATION_ERROR` | 400  | Body fails the Zod schema (`issues` present, `path` joined with `.`) |
| `NOT_FOUND`        | 404  | Resource or gated endpoint not available |
| `INTERNAL_ERROR`   | 500  | Unexpected failure (details logged server-side, never returned) |

Unsupported methods return 405 (Next.js default).

## Endpoints

### `GET /api/services`

200 → `{ "data": ServiceCategory[] }` (SPEC-003 content model). Static (`force-static`).

### `GET /api/plans`

200 → `{ "data": Plan[] }`. Static (`force-static`).

### `POST /api/diagnosis`

Body: `DiagnosisAnswers` (SPEC-004). Unknown keys are ignored.

- 200 → `{ "data": DiagnosisResult }`
- 400 `INVALID_JSON` / `VALIDATION_ERROR` (one issue per missing/invalid answer)

Stateless: nothing is stored. The diagnosis is only stored when the user submits the lead form.

### `POST /api/leads`

Body: `ContactLeadInput | DiagnosisLeadInput` (SPEC-005), discriminated by `source`.

- 201 → `{ "data": { "id": string, "receivedAt": string } }`
- 400 `INVALID_JSON` / `VALIDATION_ERROR`

### `GET /api/leads`

- When `isAdminEnabled()`: 200 → `{ "data": Lead[] }` newest first, `Cache-Control: no-store`.
- Otherwise: 404 `NOT_FOUND` (the endpoint does not advertise its existence).

### Later — `PATCH /api/leads/:id`

Update `status`. Requires authentication; not implemented in v1.

## Acceptance criteria

- [ ] AC1 — Integration tests call the exported handlers with `Request` objects and cover: success,
      invalid JSON, missing fields, invalid values and recommendation content.
- [ ] AC2 — No handler contains scoring, recommendation or lead-building logic.
- [ ] AC3 — `GET /api/services` and `GET /api/plans` are prerendered at build time.
- [ ] AC4 — Error responses never include stack traces or internal messages.
